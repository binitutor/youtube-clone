************ table 1: thp_users

** capture authenticated user accounts
    after token is used to activate the account

** columns:
    id (auto increment)
    fullname
    email
    contact
    address
    username (unique email address)
    temp_token
    user_submissions [app_id1, app_id2]
        if email address found or if user already logged in,
        - create new record for each submission under apps
        - append app id to this column
    account_type    (1, 2, 3, 4, 5, 6, 7)
        or (20001, 20002, 20003, 20004, 20005, 20006, 20007)
        20001 = admin (developer)
        20002 = user (activated using temp token)
        20003 = viewer (assistant to tesfu)
        20004 = reviewer (tesfu)
        20005 = teacher (course admin)
        20006 = student account (activated by course admin)
        20007 = auditor (optional)
    date_created    current_timestamp
    account_status  (0 or 1 for inactive to active)

************ table 3: thp_activities

** tracks activity from every engagement by everyone.
** types of activities
    action_types
    [
      public (for everyone):   submit_new_app, login, logout, 
                activate_account, session_length 
                (track session length at logout)

      user:     address_change, phone_num_change, preference_change
      viewer:   view_accounts, view_applications, view_documents
      reviewer: manage_accounts, activate_user, deactivate_user,
                update_status
      admin:    ...
      auditor:  login, logout, view_activities, view_changes
    ]

** columns:
    id (auto increment)
    action_date (current_timestamp)
    username (email address if applicable)
    action_type: keyword from actions table
    action_detail: user account seb@example.com changed their address from [old add lane] to [new address] on 2024-03-10 at 14:33:00.

*********** AUTHENTICATION **************

Step 1: index.php
- person arrives at index.php
- script checks if login_id session is set.
  login_id == column: id in users table.
- if false, person is not authenticated.
  user is redirected to login.php
- if true, person is authenticated (as admin or user)
  script checks if page value is set
  if there is specific page value, it loads that.
  if not, it loads home.php

Step 2: login.php
- script checks if login_id session is set.
- if true, user is redirected back to index 
  with page value set to home
- if false, it provides the login form

Step 3: home.php
- for authenticated user
- provides logout button
- if login_type==1, its an admin person
  displays admin content
- if login_type==2, its a user person
  displays user content
